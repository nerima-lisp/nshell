# nshell 機能デザイン — 必要十分で、人にも AI にも使いやすいシェルへ

nshell (main, v0.7.0) は S式のコマンド言語、fish 風の対話体験、AI 支援までを持つ一方、2 系統のパーサや fish 形式のビルトインのような二重の仕組みと、製品より大きい計測・契約の層を抱えています。この設計は、毎日使うものを磨き、二重の仕組みを外し、人と AI が同じシェルを同じ規則で使える形にまとめたものです。

人間に

fish の気持ちよさに、S式の表現力と安全判定の情報を足す。vi は fish と同等、表示はブロック・表・パレットまで。

→ U1〜U4・U8・U9・07

AI に

推測のいらない構造。1 つの応答の型、安定したエラーコード、実行前の explain、承認の流れ。人と同じシェルを共有できる。

→ 02・U5〜U7・09

毎日に

壊れない・失わない・どこでも動く。二重実装と計測の層を外し、残したものを確かめられる形にする。

→ 08・01・I1〜I10

## 主な決定

vi モードは残し、fish_vi_key_bindings と同等にする (07)

cl-prolog-kit は知識ベースの中核として作り直す (06)

AI プロバイダは Claude Code (既定)・Codex・Ollama から選ぶ (09)

名前解決は PATH に依らない固定の順序。値の位置のコマンドは capture などで明示 (L2・L4)

bare-line の制御構文・fish 形式のビルトイン 10 個・計測と契約の層を外す (01・L5)

既定テーマは dracula。表示は ui :rich / :classic / :plain から選べる (U1・U9)

テレメトリなし。v1.0 は日常使いの合格基準 7 項目で判定 (08)

## 設計原則

### 01 1 つの言語

S式を正とし、bare-line は単純コマンド・パイプ・リダイレクトだけの近道にする。規則は PATH に依らず決まる (L0〜L7)。

### 02 構造化データが先

builtin は値 (レコード) を返し、文字列は表示の最後でだけ作る。JSON は第一級の出力。

### 03 同じコア、3 つの入口

対話 REPL・スクリプト・機械向け (--json / --serve / MCP) が同じ評価器と同じ安全判定を通る (04)。

### 04 知識は規則で持つ

危険度・効果・診断・補完の文法を cl-prolog-kit の 1 つの知識ベースに置く。理由が説明でき、人も AI も足せる (06)。

### 05 必要十分

毎日使うかと、AI・スクリプトから効くかで選ぶ。どちらでもないものは外す (01)。

### 06 確定は人が

AI の提案は必ず人の Enter を通る。AI からの confirm は承認がなければ実行しない (U3・U7)。
