# コマンド言語仕様 — S式を正、bare-line は近道

main (v0.7.0) を実際にビルドして 145 通りの入力を流した結果を出発点に、曖昧な点と、実装と文書が食い違う点をすべて決めました。各章の「〜する」は必須の規則です。L7 に現在の動作との差分をまとめています。

全体の手触り

```
;; S式: Lisp とコマンドが同じ木の中にある
(defcmd deploy (env)
  (let ((rev (capture (git rev-parse --short HEAD))))
    (if (git diff --quiet)                  ; 条件: 終了コードで真偽
        (| (echo deploying ,rev to $env)
           (tee -a deploy.log))
        (echo "dirty tree" >&2))))

# bare-line: いつものシェルの近道
deploy staging && echo done
echo (date) (+ 1 2)          # ( … ) は置換
```

12 の決定

D1

2 つの読み方

先頭の非空白文字が ( なら S式、そうでなければ bare-line。1 つの入力の中で混ぜない。

D2

大文字小文字

Lisp の部分は CL と同じく大文字に揃えて読む。コマンドの部分は書いたまま。

D3

名前の解決

PATH の中身に依らない固定の順序で決める。CL と重なる 5 つの名前は固定表で決める。

D4

引数の中の ( … )

置換。コマンドなら出力、Lisp なら値。Lisp の中の ( … ) は普通の呼び出し。

D5

値の位置のコマンド

直接は書けない。capture・capture-lines・status・run で欲しいものを明示する。

D6

条件の位置のコマンド

終了コードで真偽。and・or・not も、どこに書いても同じ。

D7

値から引数への変換

1 つの表で決める。nil は引数なし、リストは ,@ が必要。

D8

シェル変数

文字列のリスト。$xs は要素ごとに別の引数になる。

D9

関数

defun は Lisp 関数、defcmd はコマンド (引数は語)。

D10

bare-line

単純コマンド・パイプ・リダイレクト・&& || ; & だけ。制御構文は実行前に拒否する。

D11

スクリプト

最後まで読んでから実行する。構文エラーがあれば何も実行しない。

D12

レコードと JSON

レコードは keyword をキーにした plist。JSON との変換規則を固定する。
