# 日常使いできる堅牢さ

毎日のログインシェルにするには、機能よりも「壊れない・失わない・どこでも動く」が先です。nshell は端末の復元、履歴のロック、読み込み時評価の禁止など土台が既にあるので、その上に足りないものを積みます。

## 日常使いの合格基準

v1.0 を名乗る前に、次をすべて満たします。

作者以外の 5 人以上が 2 週間ログインシェルとして使い、端末が壊れる・入力できなくなる不具合が 0 件 (外部利用者による試用は、P0〜P6 の計画には入れない)

クラッシュしても端末が戻り、履歴が失われない (故意にクラッシュさせるテストで確認)

init.lisp を壊しても --safe で必ず起動できる

「どこでも動く」の端末・tmux・ssh・Emacs の確認表がすべて通る (計画で扱うのは CI で埋められる行だけ。GUI 端末とスクリーンリーダーでの確認は計画に入れない)

性能の予算 6 項目を、v0.7.0 の基準に対するラチェットとして守っている

パーサと S式リーダーの fuzz を毎日回し、未解決のクラッシュが 0 件

bug-report だけで再現に必要な情報が揃う

### 端末を壊さない・固まらない

|   |   |   |
|---|---|---|
| 終了時の端末復元 | [あり] | REPL を unwind-protect で囲み、raw mode を必ず戻す |
| 想定外のエラーからの復帰 | [追加] | REPL の 1 周ごとに全エラーを捕まえ、handler-bind で取ったバックトレースをクラッシュログに書いてプロンプトへ戻る。バッチでもクラッシュログを書く。「同じ所」は condition の型と最も内側の nshell のフレームで判定し、3 回続いたら実行中のジョブを一覧表示してから、--safe で re-exec するか尋ねる。P0-4 での決定: クラッシュとして捕まえるのは、コマンド行の実行、キー入力の処理、端末の初期化より後のトランポリンの各段の 3 か所である。内側で捕まえたエラーは外側で重ねて扱わない。terminal-mode-operation-failed は従来どおりセッションを終える。スクリプトの構文エラーには位置つきの診断を出し、クラッシュログは書かない。次の 2 種類のエラーは表示と終了コードを従来どおりとし、クラッシュログを書かず、連続の回数にも数えない。1 つは nshell のエラーコードを持つ condition (nshell-error-code-mixin) で、nshell が意図して出す診断である。もう 1 つは利用者が書いた Lisp のコードのエラーで、最も内側の nshell のフレームが %eval-host-function-call (評価器が利用者の引数で Lisp の関数を呼ぶ所) であるものを指す。このエラーのあと、対話ではプロンプトへ戻り、バッチとスクリプトは終了コード 1 で終わる。利用者のコードから呼んだ builtin の中のエラーは、その内側に nshell のフレームがあるので、クラッシュとして扱う。storage-condition は利用者のコードが原因でもクラッシュとして扱う。SBCL がコンパイルして実行する形 (`(the fixnum "a")` や labels)、`(assert nil)`、評価器が自分で出すエラー (`(dolist (x 1) x)`)、コマンドとして解決される head (`(apply #'car '(1))`) も、最も内側の nshell のフレームが別になるため、クラッシュとして扱う。「最も内側の nshell のフレーム」は NSHELL または NSHELL.* のパッケージの記号を含むフレームで、利用者の定義 (NSHELL.USER) は数えない。バックトレースは unwind する前にフレーム名だけを取り、引数は storage-condition でないときに限り印字する。ファイルへの書き込みは unwind した後に行い、書けなかったときは理由を 1 行出してプロンプトへ戻る。連続の回数は対話セッションでだけ数え、コマンドが最後まで実行されたら 0 に戻す。そのため再起動の質問が出るのは、同じ所で失敗するコマンドを、成功するコマンドを挟まずに 3 回続けたときだけである。re-exec は nshell の実行ファイルから動いているときだけ行い、元の引数のうち値を取らず --safe とぶつからないフラグ (-i・-l・-e・--no-config・--no-history・--private) を引き継ぐ。exec は端末を元に戻してから行う。質問への答えが読めない (入力の終わり) ときはセッションを終える |
| 安全モード | [追加] | nshell --safe (NSHELL_SAFE=1 でも同じ): init.lisp・conf.d・.nshell.lisp・rules.pl・AI・functions の自動読み込み・NSHELL_PROMPT を読まずに起動。履歴は読む。--config との併用は使い方のエラー。プロンプトには利用者の書式の外に固定で `[safe] ` を出す。init.lisp を壊しても必ず入れる。P0-5 での決定: NSHELL_SAFE は NSHELL_HISTORY_PRIVATE と同じく、空、0、false、no 以外の値で有効にする。--safe には否定形がないので、NSHELL_SAFE の値によらず有効になる。NSHELL_SAFE で有効にしたときも --config との併用は使い方のエラーにする (どちらかの指定を黙って捨てないため)。NSHELL_RIGHT_PROMPT も読まない。安全モードはセッションごとの状態ではなくプロセス全体で 1 つの事実とし、main がオプションと NSHELL_SAFE を読んだ直後、セッションやスレッドを作る前に `nshell.application:*safe-mode-p*` の大域値を 1 度だけ設定する。動的束縛し直さないので、パイプラインのワーカースレッドも同じ値を読む。読み込み処理はすべてこの値だけを見て判断し、argv や環境変数を個別に読み直さない。対象はすべての入口で、対話セッション、-i -c、標準入力のバッチ、--command、スクリプトのどれでも、その入口が読むもののうち上の対象を読まない。バッチ、--command、スクリプトはもともと init.lisp・conf.d・AI を読まないので、止まるのは functions の自動読み込みと、prompt 組み込みコマンドが返す NSHELL_PROMPT・NSHELL_RIGHT_PROMPT になる。[safe] の印は対話セッションのプロンプトにだけ出る |
| メモリとスタックの枯渇 | [追加] | storage-condition とスタック溢れを捕まえて評価を中断。ヒープの上限は起動オプションで |
| 入力を止めない | [強化] | git の問い合わせは既にタイムアウトつき。補完・知識ベース・プロンプトの外部問い合わせもすべて上限時間と深さ制限を持つ |
| シグナル | [強化] | SIGINT・SIGTSTP・SIGCHLD・SIGWINCH・SIGHUP は処理あり。SIGHUP ではジョブに伝えて履歴を書いてから終了する順序をテストで固定 |
| ゾンビと孤児 | [強化] | timeout はプロセスグループごと停止 (既存)。終了時に残ったジョブを一覧して確認 |

### データを失わない

|   |   |   |
|---|---|---|
| 履歴の同時書き込み | [あり] | ロックファイルと mutex、0600、O_NOFOLLOW で開く (既存) |
| 履歴の破損からの回復 | [追加] | 読めない行は飛ばして続行し、壊れた元ファイルは `<file>.corrupt-<n>` へ退避。件数の上限は 10 万件 (set で変えられる) で、超えた古い分は消さずに `<file>.1` へ移す |
| 形式の版 | [追加] | nshell が生成する状態 (履歴・trust の DB・出力ストア) にだけ schema_version を持たせ、上げるときは自動移行と退避。設定ファイルには持たせない |
| 設定の誤り | [強化] | 構文エラーでもプロンプトまで進む (既存)。どの行かと直し方を表示 |
| 読み込み時の評価を禁止 | [あり] | S式と履歴の読み込みで *read-eval* を nil にしている (既存)。AI からの入力でも #. が動かないことをテストで固定 |

### どこでも動く

|   |   |   |
|---|---|---|
| ログインシェルとして | [強化] | chsh で設定しても安全なこと: -l、-c の /bin/sh 委譲、scp / rsync / ssh からの非対話起動を CI で確認 |
| エディタ連携 | [追加] | VS Code・JetBrains の -ilc による環境取得、Emacs の shell-mode と vterm (TERM=dumb は簡易表示に) |
| 端末の組み合わせ | [追加] | iTerm2・Terminal.app・WezTerm・kitty・Alacritty・Ghostty・GNOME Terminal・Windows Terminal (WSL)・tmux・screen・ssh 越し。リリースごとの確認表。計画で扱うのは CI で埋められる行だけで、GUI 端末での確認は入れない |
| 文字 | [強化] | 不正な UTF-8 のファイル名や出力でも落ちない。絵文字の結合・結合文字・East Asian 曖昧幅 (既存) |
| 変わったファイル名 | [追加] | 空白・改行・先頭の - ・非 UTF-8 のバイトを含む名前で、補完・glob・展開が正しく動く。非 UTF-8 の名前のテストは Linux でだけ動かす |
| 大きな入力 | [追加] | 履歴 10 万件、数万ファイルのディレクトリ、非常に長い行でも遅延が予算内 |

### 安全

|   |   |   |
|---|---|---|
| プロジェクト設定 | [追加] | .nshell.lisp は nshell trust で許可したものだけ読む。内容が変わったら再確認。内容の比較には cl-crypto-kit の SHA-256 を使う |

## 性能の予算

絶対値の目標は置きません。P0 で v0.7.0 の基準と計測の仕組みを作り、重い NFR 計測一式の代わりにこの 6 つを測ります。予算は v0.7.0 の基準に対するラチェット (悪化を許さない上限) で、計測はローカルで行います。キー入力・起動・描画・履歴に触れる変更は、そのつど基準と比べます。

|   |   |
|---|---|
| 起動 (warm) | p95 が基準より悪化しない |
| 起動 (cold) | p95 が基準より悪化しない |
| キー入力 → 描画 | p99 が基準より悪化しない |
| Tab 補完の表示 | p99 が基準より悪化しない |
| プロンプト表示 | p95 が基準より悪化しない (git は非同期) |
| メモリ | 基準より悪化しない。soak の間に増え続けない |

v0.8 の作業の前に、P0 で既知の性能の負債を直します。キーごとの `snapshot.json` の書き込み、伸びていくコマンド名での PATH 全ディレクトリの stat、Ctrl-R と履歴の移動での履歴ファイル全体の読み直しの 3 つです。

## テストの組み立て

- 単体: reducer・パーサ・展開・知識ベースの規則 (端末なし)。
- property-based と fuzz: パーサと S式リーダーにランダム入力を GitHub Actions の cron で毎日流し、落ちない・止まらないことを確かめる。
- golden: --json の出力を固定 (シナリオの後継)。
- 差分テスト: POSIX と同じと言っている展開 (${x:-y} など) は bash (nixpkgs のもの) と結果を比べる。
- PTY の結合テストは少数精鋭。端末の組み合わせはリリースごとの確認表で。
- soak: 台本どおりのキー入力を流し続け、メモリと遅延を記録。ローカルで 6 時間 × 4 回を連結し、履歴・出力ストア・RSS の推移を次の回へ引き継ぐ。

## リリースと不具合対応

- semver に加え、--json と MCP の nshell_api は別の版番号で管理。廃止は 1 リリース警告してから。
- CHANGELOG と、破壊的変更ごとの移行ガイド。
- stable と nightly の 2 チャンネル。nixpkgs と Homebrew への提出は P0〜P6 の計画に入れない。
- nix profile rollback で前の版に戻せることを案内。
- クラッシュログは `$XDG_STATE_HOME/nshell/crash/<時刻>.log` に書く (XDG_STATE_HOME が未設定なら `~/.local/state/nshell/crash/`)。ディレクトリは 0700、ファイルは 0600 で、秘匿化を通し、HOME は `~` に置き換える。P0-4 での決定: XDG_STATE_HOME が相対パスなら未設定と同じに扱う。ファイル名は UTC の時刻をマイクロ秒まで入れたもので、O_EXCL で作る。同名のファイルがあれば `-1` から順に番号を付ける。秘匿化 (assistant の redact-lines) はメッセージとフレームの引数にかけ、フレームの関数名にはかけない。関数名はコードの識別子で、20 文字以上の語を伏せる規則をかけると、長い関数名がすべて伏せられるからである。
- nshell bug-report が版・OS・端末・設定の概要・直近のクラッシュを集めて issue の下書きを標準出力に出す。送信はしない (テレメトリなし)。値を出す環境変数は TERM・COLORTERM・LANG・LC_* だけ。設定ファイルは有無・サイズ・sha256 と、設定済みの NSHELL_* の名前だけを出す。
- bug-report・doctor・init など nshell のサブコマンドの名前は予約語として、同名のスクリプトより優先する。同名のスクリプトは `nshell ./doctor` か `nshell -- doctor` で実行する。
- エラーコードごとに説明ページ。help はオフラインで完結。
