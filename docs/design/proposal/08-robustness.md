# 日常使いできる堅牢さ

毎日のログインシェルにするには、機能よりも「壊れない・失わない・どこでも動く」が先です。nshell は端末の復元、履歴のロック、読み込み時評価の禁止など土台が既にあるので、その上に足りないものを積みます。

## 日常使いの合格基準

v1.0 を名乗る前に、次をすべて満たします。

作者以外の 5 人以上が 2 週間ログインシェルとして使い、端末が壊れる・入力できなくなる不具合が 0 件

クラッシュしても端末が戻り、履歴が失われない (故意にクラッシュさせるテストで確認)

init.lisp を壊しても --safe で必ず起動できる

「どこでも動く」の端末・tmux・ssh・Emacs の確認表がすべて通る

性能の予算 6 項目を CI で守っている

パーサと S式リーダーの fuzz を毎日回し、未解決のクラッシュが 0 件

bug-report だけで再現に必要な情報が揃う

### 端末を壊さない・固まらない

|   |   |   |
|---|---|---|
| 終了時の端末復元 | [あり] | REPL を unwind-protect で囲み、raw mode を必ず戻す |
| 想定外のエラーからの復帰 | [追加] | REPL の 1 周ごとに全エラーを捕まえ、バックトレースをクラッシュログに書いてプロンプトへ戻る。同じ所で 3 回続いたら安全モードへ |
| 安全モード | [追加] | nshell --safe: 設定・AI・プロジェクト設定・ユーザー規則を読まずに起動。init.lisp を壊しても必ず入れる |
| メモリとスタックの枯渇 | [追加] | storage-condition とスタック溢れを捕まえて評価を中断。ヒープの上限は起動オプションで |
| 入力を止めない | [強化] | git の問い合わせは既にタイムアウトつき。補完・知識ベース・プロンプトの外部問い合わせもすべて上限時間と深さ制限を持つ |
| シグナル | [強化] | SIGINT・SIGTSTP・SIGCHLD・SIGWINCH・SIGHUP は処理あり。SIGHUP ではジョブに伝えて履歴を書いてから終了する順序をテストで固定 |
| ゾンビと孤児 | [強化] | timeout はプロセスグループごと停止 (既存)。終了時に残ったジョブを一覧して確認 |

### データを失わない

|   |   |   |
|---|---|---|
| 履歴の同時書き込み | [あり] | ロックファイルと mutex、0600、O_NOFOLLOW で開く (既存) |
| 履歴の破損からの回復 | [追加] | 読めない行は飛ばして続行し、元ファイルを退避。件数の上限とローテーション |
| 形式の版 | [追加] | 履歴・設定・出力ストアに schema_version を持たせ、上げるときは自動移行と退避 |
| 設定の誤り | [強化] | 構文エラーでもプロンプトまで進む (既存)。どの行かと直し方を表示 |
| 読み込み時の評価を禁止 | [あり] | S式と履歴の読み込みで *read-eval* を nil にしている (既存)。AI からの入力でも #. が動かないことをテストで固定 |

### どこでも動く

|   |   |   |
|---|---|---|
| ログインシェルとして | [強化] | chsh で設定しても安全なこと: -l、-c の /bin/sh 委譲、scp / rsync / ssh からの非対話起動を CI で確認 |
| エディタ連携 | [追加] | VS Code・JetBrains の -ilc による環境取得、Emacs の shell-mode と vterm (TERM=dumb は簡易表示に) |
| 端末の組み合わせ | [追加] | iTerm2・Terminal.app・WezTerm・kitty・Alacritty・Ghostty・GNOME Terminal・Windows Terminal (WSL)・tmux・screen・ssh 越し。リリースごとの確認表 |
| 文字 | [強化] | 不正な UTF-8 のファイル名や出力でも落ちない。絵文字の結合・結合文字・East Asian 曖昧幅 (既存) |
| 変わったファイル名 | [追加] | 空白・改行・先頭の - ・非 UTF-8 のバイトを含む名前で、補完・glob・展開が正しく動く |
| 大きな入力 | [追加] | 履歴 10 万件、数万ファイルのディレクトリ、非常に長い行でも遅延が予算内 |

## 性能の予算

目標値は現状を測ってから決めます。重い NFR 計測一式の代わりに、この 6 つだけを CI で毎回測って守ります。

|   |   |
|---|---|
| 起動 (warm) | p95 ≤ [目標] ms |
| 起動 (cold) | p95 ≤ [目標] ms |
| キー入力 → 描画 | p99 ≤ [目標] ms |
| Tab 補完の表示 | p99 ≤ [目標] ms |
| プロンプト表示 | p95 ≤ [目標] ms (git は非同期) |
| 24 時間の連続利用 | メモリの増加なし |

## テストの組み立て

- 単体: reducer・パーサ・展開・知識ベースの規則 (端末なし)。
- property-based と fuzz: パーサと S式リーダーにランダム入力を毎日流し、落ちない・止まらないことを確かめる。
- golden: --json の出力を固定 (シナリオの後継)。
- 差分テスト: POSIX と同じと言っている展開 (${x:-y} など) は bash と結果を比べる。
- PTY の結合テストは少数精鋭。端末の組み合わせはリリースごとの確認表で。
- 24 時間の soak: 台本どおりのキー入力を流し続け、メモリと遅延を記録。

## リリースと不具合対応

- semver に加え、--json と MCP の nshell_api は別の版番号で管理。廃止は 1 リリース警告してから。
- CHANGELOG と、破壊的変更ごとの移行ガイド。
- stable と nightly の 2 チャンネル。nixpkgs と Homebrew は roadmap どおり。
- nix profile rollback で前の版に戻せることを案内。
- クラッシュログは ~/.local/state/nshell/crash/ に。nshell bug-report が版・OS・端末・秘匿化した設定・直近のクラッシュを集めて issue の下書きを作る。送信はしない (テレメトリなし)。
- エラーコードごとに説明ページ。help はオフラインで完結。
