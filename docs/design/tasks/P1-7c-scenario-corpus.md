# P1-7c シナリオコーパスの選別

`t/scenarios/` のシナリオ 260 本を 1 本ずつ判定した一覧です。v0.8 では残すシナリオを 30〜40 本に絞ります。この文書は [P1-machine-interface.md](P1-machine-interface.md) の P1-7 の最後の項目にあたる選別の結果です。

シナリオを実際に消したり golden へ移したりするのは、[P2-language-and-cuts.md](P2-language-and-cuts.md) の P2-6 です。P2-6 ではこの一覧を作業の指示として使います。判定を変えるときは、この文書の該当する行と、集計と残す本数の内訳を直してから作業してください。P2-6 の「batch のものは golden へ移す」より、この一覧の判定を優先します。batch でも、ほかのテストが同じことを確かめているものは [削除] にしています。

シナリオを消したら、`t/scenarios/expected-scenarios.json` からもその ID を外します。`scripts/run-scenarios.py` は、シナリオのファイルとこのマニフェストが一致しないと失敗します。

## 判定の基準

- [残す]: PTY でしか確かめられない対話の挙動で、ほかのテストが確かめていないもの。
- [残す・CI 指定]: CI が ID を指定しているもの。`.github/workflows/scenarios.yml` が `--scenario-id`・`--scenario-binary`・`--scenario-temp-dir` で指定している 7 本 (P12・L02・T06・J05・Q03・Q07・Q08) です。`flake.nix` は ID を指定していません。
- [golden へ移す]: `nshell --json --command` の出力として固定でき、golden の形 `{input, env, files, expected}` で書けるもの。理由の欄には `input`・`env`・`files` への写し方を書いています。
- [削除]: ほかのテスト (`t/unit`・`t/integration`・`t/e2e`・`t/spec`・`t/golden`) が同じことを確かめているもの。理由の欄には確かめているテストのファイルと名前を書いています。残すシナリオが同じことを確かめている場合は、そのシナリオの ID を書いています。
- [削除 (F4)]: P2-6 で完了した削除 (F4) で外した機能 (slurp / barf、マウス、Ctrl-X の再実行、Alt-C / Alt-L / Alt-U / Alt-T の既定の割り当て) のシナリオ。
- [削除 (先にテストを足す)]: PTY がなくても確かめられるのに、いまはどのテストも確かめていないもの。理由の欄の「削除の前に」に書いたテストを P2-6 で先に足し、そのあとでシナリオを消します。

golden に書けない batch のシナリオもあります。標準入力やスクリプトファイルとしての起動が要るもの、生のバイト列を比べるものです。これらはほかのテストが確かめていれば [削除]、確かめていなければ [削除 (先にテストを足す)] にしました。

## 補足

- 同じことを確かめていた 3 組は、どれも片方を [削除] にしました。U02-osc-133-markers は F07-approx-osc-133-prompt と同じく、OSC 133 の順序を確かめています。E02-bg-resumes-stopped-descendant は T3-R03-fg-resumes-stopped-descendant と同じく、止めたグループを killpg で再開する経路を通ります。F01-approx-cooked-mode-after-crash は、D11-approx-cooked-mode-after-crash と手順も期待値も同じです。
- Q05-git-probe-timeout-does-not-block-input は [削除] にしました。[P2-language-and-cuts.md](P2-language-and-cuts.md) の P2-6 は、前倒しで外した NFS VM 専用のジョブと試行に、このシナリオは含まれないと書いています。シナリオそのものは、ほかと同じ基準で判定しました。遅い git のプローブで入力が止まらないことは、残す L02 と unit テストが確かめています。
- A06-login-environment は [削除] ですが、ラッパーが USER・SHELL・SHLVL を保つことは、いまどのテストも確かめていません。P2-6 で、残す A04-A05-login-path-handoff にこの条件を足します。
- C06-builtin-reads-stdin を golden へ移すときは、`string upper` の部分だけを移します。`count` は P2-6 で消すビルトインです。
- C08 は v0.8 で E_UNSUPPORTED_SYNTAX になる bare-line のヒアドキュメント ([L5](../language/L5-bare-line.md) 5.3) を、v0.7 の挙動のまま固定しています。[削除] にしましたが、確かめているテストとして挙げた e2e も v0.7 の挙動を前提にしています。この e2e は、P2-4 で bare-line の here-doc を拒否するときに書き換えが要ります。
- [golden へ移す] の 21 本はどれも実際に `--json` で実行していません。とくに次の点は移すときに確かめてください。
  - E04: disown した `sleep` が出力のパイプを持ったまま残り、応答を待たせないか。
  - K06・N05・O15: スクリプトファイルからの起動を `--command` に変えても、出力が同じか。
  - O15: ASDF のコンパイル結果の置き場所がホストのキャッシュに左右されないか。
  - P07: `--json` で theme の設定処理が入るか。
  - Q01: デバッグ出力がないことを、比べない `error.message` ではなく stdout と stderr で固定できるか。
  - J03: 相対パスの CDPATH が `$WORK` を基準に解決されるか。
- [削除] の判定は確かめているテストの本文を読んで決めました。テストは実行していません。「ほかのテストが確かめていない」という判定は、ファイル名と文字列の検索にもとづきます。そのため、名前が違うテストを見落としている可能性があります。
- PTY を使う `t/e2e` と `t/integration` のテストは、Nix のサンドボックスでは skip されます。これらのテストを「確かめているテスト」に挙げた [削除] の行は、消す前にホストで `NSHELL_TEST_PTY=1 CI=1` を付けてそのテストを実行し、通ることを確かめてください。
