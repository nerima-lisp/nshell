# 人間の UX ③ AI の提案を受けるとき

? でも Ctrl-] でも ai why でも agent でも、提案は同じパネル・同じキー。提案は入力欄の普通のテキストとして入り、確定は必ず人の Enter です。AI への質問になるのは、行頭の ? の後ろに空白があるとき (`? `) だけで、`?foo` は glob のままです。

*? / Ctrl-] からの提案*

```
~/src/nshell main ❯ ? count lisp files changed this week
╭ proposal · ● safe
│ (| (git log --since=1.week --name-only --format=)
│    (grep "\\.lisp$") (sort -u) (wc -l))
│ effects: reads git history
╰ Enter 実行 · Alt-E 編集 · Tab 説明 · Esc 破棄
```

*agent の各ステップも同じパネル*

```
agent · free disk space in this repo        step 2/10
  ✓ du -sh * | sort -h                 0.4s
╭ next · ● confirm
│ rm -r target/
│ effects: deletes target/ (1.2 GB, 3,140 files)
│ why: build output, regenerated by cargo build
╰ Enter 実行 · Alt-E 編集 · Esc とばす · Ctrl-C 中止
```

## キーは 1 組だけ

いまは agent が e / s / q、ask と Ctrl-X が別の確認キーで、編集中に q や s が文字として入る混乱もあります。すべての AI パネルで次の 5 つに統一します。パネルはモーダルで、開いている間のキーはパネルが受け取ります。

|   |   |   |
|---|---|---|
| Enter | 実行する | どの提案でも同じ。AI の提案が block なら実行できない |
| Alt-E | 入力欄で編集する | パネル内の Alt-E は提案を入力欄へ移す。提案はただのテキストなので、普段のキー操作がすべて使える。入力欄での Alt-E は外部エディタのまま |
| Tab | 説明を開く / 閉じる | 効果・判定の理由 (規則名)・各引数の意味 |
| Esc | この提案を捨てる | agent では次のステップへ |
| Ctrl-C | タスクを中止 | シェルの Ctrl-C と同じ意味 |

## 信頼できる見せ方

- 提案には必ず効果 (読む・書く・消す・ネットワーク) を出す。危険度だけでは判断できない。
- 判定の理由は規則名つき (例: classify/force-push)。Tab で全文。
- AI が実行したコマンドは履歴に origin = ai で残り、プロンプトの {ai} に件数が出る。origin:ai での検索は、既存の proposal と agent の記録にも一致する (U7)。
- ストリーミング中は 1 行の進行表示だけ。長い思考過程は出さない。
- 料金・トークンは ai status に。プロンプトには出さない。
