# L02: Git prompt responsiveness in a large repository

1. Prepare a disposable Git checkout containing at least 20,000 tracked files. `NSHELL_PROMPT` replaces the prompt format, so set it in the launcher environment to a unique format such as `L02_PROMPT_<run-id> {path}{git} `, retaining `{git}` so branch and dirty status remain visible.
2. Put a fake `git` first on `PATH`, outside the checkout. nshell calls it as `git -C <dir> symbolic-ref ...` and `git -C <dir> status ...`, so the fake skips the `-C <dir>` pair before it reads the subcommand. It answers `symbolic-ref` with a branch name at once, and for `status` it appends a start line to a log file, sleeps 3 seconds, and appends an end line. Start a fresh shell and use a PTY harness with a monotonic clock to measure the time from process creation to the prompt marker. Do not type the prompt marker into the shell.
3. In the same session, wait until the log shows a `status` call starting. Then type and run `echo L02_READY >> <log>` with a short relative path to the log (autosuggestion rescans each directory in the line on every key, so a path through a large directory such as `/tmp` delays the command itself), so the command appends `L02_READY` to the same log, and wait for that line to appear in the log. Judge the order from the log, not from the terminal: nshell shows the typed line in the window title before it runs the command. Exit the shell; it may wait for the sleeping `status` call before it exits.
4. Run steps 2 and 3 in each of five fresh sessions.
5. With the real `git`, confirm branch information appears. On an idle Apple Silicon macOS host and an idle CI Linux host, with the checkout, build, and terminal settings fixed for each host, collect five fresh-process warmups and then 30 fresh-process measurements of startup and of empty Enter (from sending Enter to the next prompt marker), and repeat the complete run once. Report the two medians and the sample range for each measurement, together with the repository fixture, platform, build, and sample counts.

Pass when branch information appears with the real `git`, and when in every session of steps 2 to 4 the prompt appears within 2,000 ms while `status` sleeps, the first `status` start line comes before `L02_READY` in the log, no `status` end line comes before `L02_READY`, and the shell exits cleanly. A `status` call started by a later prompt may follow `L02_READY`. The bound rationale is in `t/scenarios/README.md`. The startup and empty-Enter numbers of step 5 are recorded only and do not decide the result; the 150 ms and 60 ms targets are reported next to them. Performance is guarded by relative checks against the v0.7.0 baseline planned in task P0-7 (`docs/design/tasks/P0-foundation.md`).
